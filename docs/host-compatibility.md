# 研究工程怎样接入 Dorislab 客户端

本文解释研究代码、Agent 和 Dorislab 客户端之间的分工，以及怎样让生成的报告进入研究室。旧文档中的“宿主”就是 **Dorislab 桌面程序及其 Rust 后端**，不是 Agent，也不是远端商业服务。下文统一称为“客户端”。

## 三者各自做什么

| 对象 | 具体职责 |
| --- | --- |
| Agent | 理解用户要求，读取工程说明和代码，选择工具，编写并运行分析程序，解释结果。模型通过 Codex App Server 调用命令和编辑工具。 |
| 研究工程 | Agent 可以修改的 Python／TypeScript 源码、AGENTS.md、Skills、依赖和文档。负责计算、策略规则、指标、报告及研究页面。工程路径由本轮上下文给出，不要求 Agent 猜安装位置。 |
| Dorislab 客户端 | 受理用户消息、管理运行状态与账号数据、启动引擎、提供数据目录、登记成果身份和版本、保存历史、刷新研究室与搜索。产品数据库由这里的 Rust 代码维护。 |

例如，研究程序算出一张收益表并生成报告，是工程完成了计算和文件生成；执行 `publish` 后客户端确认保存，才是成果已进入研究室。生成文件、检查计算、构建页面、登记成果是不同步骤，各自需要实际成功，登记回执不证明研究结论或策略有效。

## Agent 能看到哪些代码和数据

不是“工程可见、数据不可见”。客户端主要把路径、目录与使用说明交给 Agent，不会预先把完整源码和所有数据塞进模型上下文；Agent 需要按任务实际读取。要区分以下对象：

| 对象 | 正常读取／修改方式 |
| --- | --- |
| 本轮研究工程源码 | Agent 可以读取和修改 `source` 指向的完整工作副本，包括 Python、前端和工程规范。 |
| 已安装行情 | 客户端给出本轮数据清单路径；工程用 `data-catalog` 查覆盖、用 `data-read` 读取实际数据，也可在 Python 中调用读取器。客户端维护的数据文件不由研究脚本改写。 |
| 用户授权材料 | 按输入路径读取 CSV、JSON、Parquet 等材料；保存实际输入身份及必要证据。 |
| 本轮计算、报告和图表 | Agent 可以在本轮 `results` 下新建目录、运行代码并写出文件。 |
| 历史正式成果 | 从 `publications.path` 对应的目录索引定位版本，再读取其中的正文、代码和证据；旧版本保持原样，修订生成新版本。 |
| 客户端产品数据库 | 存放会话、运行状态、成果 ID、版本和关联等产品记录。研究程序通过客户端提供的入口取得所需信息或登记成果，不直接查询／改写数据库表。 |

行情数据和客户端产品数据库不是同一个东西。具体数据命令、选包身份与校验见[数据、计算和环境](data-and-execution.md)。

这里的“不直接读写产品数据库”是接入约定，不等于数据库文件在操作系统层面不可见。当前启用原生命令的执行模式是完全访问；不能把文档约定说成文件系统已实施强隔离。研究脚本直接改库会绕过客户端状态、版本、文件封存和通知流程，因此不属于受支持的操作方式。

## 一项研究在代码层面怎样开始和完成

1. **客户端受理消息。** Rust 保存用户输入、模型选择和本次 AgentRun（一次对话执行）的身份与状态，再安排后台执行。
2. **客户端准备工作环境。** 将账号公共工程复制到本轮独立工作目录，创建本轮结果目录，向 Agent 提供 `source`、`results`、受管 Python／`run.py` 路径、历史成果索引和本地行情清单，随后启动或恢复 Codex App Server 会话、传入这些信息并刷新工程 Skills。不同会话不会直接共用同一份可写工作副本。
3. **Agent 选择并执行研究步骤。** 读取 AGENTS.md 和适用 Skill，确认输入与数据覆盖；通过原生命令读取数据、编写或修改程序，再运行计算。可以使用工程已有命令，也可以编写自己的分析脚本。不是每条消息都会自动执行一个固定研究流水线。
4. **工程保存并检查结果。** 在本轮 `results` 的新目录保存代码、参数、输入身份、计算结果、正文和图表。一次 AgentRun 可以包含多次 CalculationRun（一次具体计算）；对失败计算的修复与重算使用新目录，不能覆盖旧证据。
5. **工程整理，客户端保存。** `save-study` 整理计算研究的相对路径材料后调用 `publish`；Rust 校验当前执行、文件和声明路径，封存保存时的工程版本，提交数据库后返回成果 ID、版本和 URI。其他适配器仍可导出后 `publish`。
6. **客户端展示并结束运行。** 登记成功后研究室和搜索可找到成果，Agent 用回执 URI 交付，也可用 `open_content` 展示。AgentRun 成功结束时，客户端按启动基线合并本轮工程改动；有并发冲突时保留修改并提示，不覆盖公共工程。结果文件与正式登记独立于工程源码合并。

简短问答、即时查询或用户明确不保存的分析可以只回答，不强制导出登记。通用研究的文件组织和命令示例见[研究交付](study-delivery.md)，策略与运行见[回测入口](backtesting.md)。

## 将文件登记为正式成果

运行上下文中 `capabilities.artifactRegistration=true` 表示客户端提供登记入口。在当前 Dorislab Agent 终端内，用 `execution.python` 执行 `execution.launcher`（工程的 `run.py`），再传以下参数：

```text
export-analysis --bundle <已通过校验的分析目录> --output <results 下的新导出目录>
publish --package <该导出目录>
```

通用计算研究在 `artifactExecutionMaterials=true` 时使用 `save-study --request <请求.json> --output <新导出目录>`，用法见[研究交付](study-delivery.md)。无计算的阅读材料可 `export-study` 后 `publish`；日线 ETF 回测先登记策略，再按确切策略回执登记关联运行。`export-analysis` 会再次检查计算并复制证据，默认导出为 study。

`publish` 使用客户端给当前运行设置的临时本机连接。连接参数与凭据由程序读取，模型不读取、回显或手填。命令把登记请求交给 Rust 处理，Python 本身不写客户端数据库；这不是公开 HTTP 服务，在 Agent 执行结束后不可再使用。

成功输出 receipt，并另存到导出目录旁的 `<目录名>.receipt.json`。用 `[研究标题](<receipt.uri>)` 交付，点击打开该确切版本；研究室自动刷新，全局搜索查询最新版本。

回执丢失时，对**同一导出包**再次 publish 找回原回执，不要重新计算或再次 export。同一个 request_id 不能换内容。修订使用新导出目录和 `--previous <旧回执文件> --note <修订说明>`；客户端核对前一版本后分配同一成果 ID 的下一 revision。旧文件和旧引用保留；数值重算另建计算目录，纯说明修订不能声称已重算。

## 读取已有研究，以及为什么当前不能直接删除

`publications.path` 指向客户端每轮重建的只读 `host/publications.json`，包含未归档、未删除成果各历史版本的 receipt、package、已保存文件目录 directory，以及引用版本的 reference_states。按 kind/id/version 找到目标，再从目录读取正文和证据并核验清单中的 SHA-256。不要修改这个索引或 `published` 文件；索引状态为 unavailable 时，应报告读取失败，不能拿旧缓存冒充当前目录。本轮刚登记的成果可使用新回执和原导出包。

客户端只接受当前账号、本轮允许的 `results` 目录里的导出包，分配身份并将正式文件保存到 `results/published`。文件保存与数据库事务都成功才算登记完成；崩溃留下的未登记文件不会自动进入研究室。

**成果归档、恢复和永久删除只由用户在客户端界面操作，不是 Agent 工具能力。** 归档满 7 天自动删除。正常目录不列出已归档或已删除成果；仍有效成果的 `reference_states` 会按其 `references` 和 `previous` 给出引用版本的状态、标题和原摘要。`deleted_at` 非空表示已删除：只能沿历史引用解释原摘要，不能把它当作当前可用研究或尝试读取原正文、附件；不提供已删除成果的独立搜索目录。附件没有摘要。

归档不影响其他成果，历史链接仍可打开；删除只清理对应成果的封存正文和文件，原版本摘要保留用于解释旧引用。不要改产品数据库、索引或删除目录来代替用户操作。

## 成果包格式与上限

客户端只要求稳定的通用信息：成果类型、身份与版本关联、标题摘要、基础阅读／搜索文字、文件清单、来源与引用。研究内容、策略规则和指标格式由工程维护；修改它们时同步计算程序、读取页面、校验器与导出器，不要求 Rust 理解每种业务字段。

正式格式名为 `dorislab.research.artifact.v1`。Rust 的 `PublicationPackage` 是格式定义来源；随工程交付的 [JSON Schema](host-artifact.schema.json) 和前端 `publicationContracts.ts` 由它生成。自定义导出器可使用相同通用字段登记 study／strategy／run／series，`project_format` 标识工程自己的业务格式。当前不接收自定义页面入口或未知顶层字段。

可选 `execution` 声明入口和材料路径，不改变旧包的身份指纹。声明执行材料的包由 Rust 附带封存精确工程快照，内部目录 `_dorislab` 保留给客户端；工程不能在文件清单中占用它。接续命令 `prepare-publication` 校验并复制原版本到本轮 results，旧包缺少声明时明确拒绝准备执行，阅读仍可用。原工程缺失、变更或来源对话删除不影响新包的已保存快照。该快照证明保存时的字节，不认证计算结论，也不自动授权重新取得数据。

成果包必须有 UTF-8 正文、同版本检索文字、文件大小和 SHA-256 清单、来源性质及用于重复请求去重的 request_id；封面和版本关联按格式选填。路径必须在包内，拒绝链接、越界、重名或未列入清单的文件。当前上限为 256 个文件、单文件 32 MiB、总计 64 MiB；正文和检索文字各 1 MiB，PNG／JPEG／WebP 封面 1 MiB。超限应明确处理，不能删除必要证据来冒充完整交付。

## 阅读页面与工程更新

声明 `publication-reader-v1` 的工程页面可以展示正式正文和文件，并提供接续讨论与划词引用。旧工程页面不兼容时，客户端使用内置基础阅读页；没有可用工程页面构建也能按已登记引用阅读。后台构建失败会保留上一可用页面，不因此切换阅读方式；热更新不把旧正文变成新版本，普通会话或列表通知也不会刷新固定版本正文。

两套阅读页均支持清单内不超过 8 MiB 的 PNG／JPEG／WebP／SVG，以及表格、代码块的内部横向滚动。SVG 通过图片 data URL 加载，不作为内联 DOM 或脚本执行；Markdown 中的 SVG 是静态图，自定义交互图表仍需工程页面适配。封面继续使用上述位图限制。

页面通信协议 `dorislab.research.v1` 负责展示与受控操作，不是成果格式。旧演示包及专用入口已删除，列表只查询正式成果。登记关联 AgentRun 只说明来自哪轮对话，不代表客户端认证了每次计算的全过程或结论。

### 标签页状态保存（2026-10-16）

桌面入口新增可选能力 `view-checkpoint-v1`。客户端可能在非可见页面超出驻留预算或闲置后发出 `checkpoint-view`（随机 `requestId`），页面回复同 ID 的 `view-checkpoint`，包含 `safe` 与 `{schema:1, values, scroll, storage}`。文件／目录读取在途、弹窗或内容编辑未结束时 `safe:false`；客户端保留实例，不取消后台计算。工程扩展了可编辑表单或其他操作时，必须扩展此保护及快照，不能未经保存就返回 `safe:true`。

快照只含图表指标、缩放、隐藏图例、引用点、月收益展开、正文滚动与既有研究室导航状态，不含正文、图片或研究数据。客户端按账号、标签与页面构建隔离保存，成功后才回收；同构建重开经 `init.viewState` 恢复，并重新读取正式成果。新构建不应用旧快照。客户端校验消息窗口／源／通道和请求 ID，限制快照为 65536 字符，超时或写入失败保留页面并报错。旧客户端忽略新能力，旧工程不声明能力时继续驻留。

本能力是源码中的新实现，尚未随 v0.1.1 发布；需后续工程发布及客户端发布锁更新才能用于默认安装。

AGENTS.md、Skills、文档、Schema、程序和页面更新都保留本地修改；冲突时保留当前工程和最后可用构建。格式不兼容时说明哪项能力失效，保留文件与旧成果，不偷偷恢复用户修改过的规范。
